## 十条避坑速查

1. **版本号只改根目录 `VERSION`**。别在 csproj、`Info.plist`、`--version` 里另写一处，三处会自动同源。
2. **来源路径带尾部斜杠会出空名归档**。`Path.GetFileName("/a/b/")` 返回空串，输出会变成 `.7z`；所有收集出口必须统一规范化。
3. **从主卷入口解压旧式分卷时，要按整组处理**。`base.rar` 加 `base.r00` 是一个组，只处理主卷会留下孤儿成员文件、还会跳过缺卷预检。
4. **日志里有明文密码**。归档命令与原始输出明确不脱敏，日志只能本地诊断，不能外发、不能当公开附件。
5. **测试项目不在解决方案里**。它是控制台程序，必须单独指定 csproj 运行；`dotnet test` 不适用。
6. **macOS 打包前先校验二进制架构**。`7zz` 必须是通用二进制（universal），RAR 必须是 arm64；错误的 Linux 可执行文件（ELF）要在安装前就被脚本拒绝。
7. **不要用 `open -n` 启动应用**，会在访达（Finder）的最近使用区留下重复记录。
8. **切换界面语言要重启状态栏帮助进程**。那个原生小进程的菜单文案在启动时固定，运行期改不了。
9. **达到大小上限只拦「还没开始」的任务**，不杀正在跑的压缩；取消则相反，会传播到全部在途子进程，且绝不触发关机。
10. **`docs/` 里几十份「当前开发进度」只有最新一份有效**。判断现状优先读源码和 [项目运行机制分析](../docs/20261105-2243-项目运行机制分析-Claude-Opus.md)。

## 已确认被推翻或容易误读的历史结论

| 历史写法 | 实际情况（0.7.6 核实） |
| --- | --- |
| 「项目没有持续集成配置」 | 已有 `.github/workflows/release.yml`，标签触发三平台发布 |
| 「仓库携带的是单个裸 `rar` 二进制」 | 决策 B 后 `tools/rarLinux/` 是官方完整未修改分发包（12 文件），Linux 构建会整体复制 |
| 「公开仓库不携带任何第三方 RAR 二进制」 | 早期表述已作废，README 与许可风险说明已改写 |
| 「测试 24 项 / 30 项」 | 早期快照；当前控制台测试 59 项，端到端夹具 149 项 |
| 「`--version` 0.4.4 / 0.6.5」 | 早期打包验证记录里的版本号，不是当前版本 |
| 「CLI 输出英文与服务层中文混排」 | 解析成功后同步语言，该类问题已收敛 |
| 「RAR 官方分发包共 12 个文件」 | 实测 `tools/rarLinux/` 为 **11 个文件**，历史文档计数笔误 |
| 「结构化输出恒为 stdout 事件流」 | `--dry-run` 提前返回时 stdout 为空，DRY-RUN 清单走 stderr；只有真实执行才产生 NDJSON |

「用户决定保留裸二进制」与「决策更新：已改完整分发包」两段，后者才有效——这类文件尤其要通读到底。

## 实测验证（不是照抄文档）

`测试夹具/经验验证/verify.sh` 是可复跑的验证脚本：开测前先重新构建确认产物最新，
然后在系统临时目录造文件，用真实命令行核对 15 项经验结论，退出时清理全部残留。

覆盖：版本号同源、英文帮助预扫描、非法参数退出码 2、试运行不改文件、系统元数据过滤、
带尾斜杠目录不产生空名归档、带密码真实压缩→解压逐字节一致、日志权限 0600、
结构化输出排除密码、试运行不产生事件流、59 项回归测试、打包前置自检、
RAR 完整分发包文件数、7zz 版本、解决方案只含主项目。

**2026-11-05 实测结果：PASS=15 FAIL=0**。首次运行有 2 项失败，
追查后确认是历史文档写错（文件数）与漏写（试运行边界），已据此修正经验文档——
这正是要求「实际测试」而非归纳文档的价值。详细输出见
[实测验证报告](../docs/20261105-2306-经验库覆盖91篇文档与实测验证-Claude-Opus.md)。
