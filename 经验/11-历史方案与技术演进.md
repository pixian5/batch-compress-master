# 历史方案与技术演进经验

> 覆盖 `文档/` 里的详细设计文档、新旧项目对比、WinForms 补齐记录，以及 2026-08 的一批技术说明。
> 这些文档的价值是解释「为什么这样设计」，不是描述当前实现。

## 1. 旧 WinForms 实现只在 `old/`，不参与编译

项目已重构为跨平台 Avalonia（图形界面框架，Avalonia），旧界面代码整体移到 `old/`，
csproj 显式 `Compile Remove` 排除它以及 `bin/`、`obj/`、测试目录。
`文档/详细设计文档.md`、`新旧项目对比1.md`、`WinForms功能补齐记录-0.2.2.md`
描述的是旧架构，读它们只为追溯，不要照着改当前代码。

## 2. 长期文档也会过期，版本号尤其容易漂移

`文档/ARCHITECTURE.md` 开头仍写「Avalonia 12.1.1」，而当前 csproj 已是 **12.1.5**；
同一份文档还写「仓库内仍保留一份裸 `rar` 二进制」，实际已换成官方完整分发包。
`AVALONIA_VERSION.md` 记录的升级理由仍有参考价值，但版本数字必须回源码核对。

## 3. 命令行解析器为什么自研

`2026-08-06-Avalonia12与命令行解析器更新.md` 记录了从 `System.CommandLine` 迁到项目内
自研 `CommandLineHandler` 的原因：预览期 API 频繁变更会影响发布。
配套约束是：动词与旧开关都要兼容，且 `--help` / `--version` / 参数错误必须在初始化界面框架之前处理。

## 4. 归档后端参数严格隔离

`2026-08-05-WinRAR-参数执行重构.md` 与 `2026-08-07-RAR与7z边界.md` 反复强调：
WinRAR/RAR 的参数由 `WinRarCommandBuilder` 生成，`7zz` 的由 `SevenZipCommandBuilder` 生成，
两者都只把独立参数交给 `ArchiveProcessRunner`，不能混在一个构建器里，也不能拼成完整命令字符串。
恢复记录（`-rr`）、快速打开、锁定、注释文件是 RAR 专属；`7zz` 侧对应的是固实、文件名加密、创建后测试等。

## 5. 文件「是否适合再压缩」只是扩展名启发式

`RAR与7z边界.md` 里的可压缩/不可压缩清单（txt、源代码适合；jpg、mp4、zip 通常已压缩）
用于 RAR 的 `-ms` 仅存储判断，**不是内容检测**。PDF、ISO、WAV 等要看实际内容。
不要把这个清单理解成「按扩展名排除文件」——程序不会因扩展名把文件踢出归档。

## 6. 密码兼容与关机交互是历史包袱

`2026-08-07-密码依据与关机交互.md` 记录：密码派生用 MD5 是为兼容旧版密码，
**不是密码学保护**；关机与取消关机由系统集服务按平台调用，失败不能中断归档任务。
改这块要先想清楚存量归档能不能解开。

## 7. 跨平台获取 RAR 的方式演进过

`优化跨平台获取rar文件方式.md`、`rar目录获取方式.md`、`跨平台功能补充评估.md`
记录了从「找注册表/固定目录」到「系统安装 + 环境变量注入」的变化。
当前口径：Windows 查注册表与标准安装目录；Linux/macOS 用系统安装、
`BATCHCOMPRESS_RAR_PATH` 指定单个可执行文件，或私有打包时 `BATCHCOMPRESS_RAR_DIR` 注入目录。

## 8. 五项归档修复与解压解析是排障字典

`2026-08-06-五项归档修复.md`、`2026-08-08-解压解析实现.md`、
`2026-08-06-官方7z支持.md` 记录了分卷、缺卷、密码、附件、输出路径等一批早期缺陷。
遇到类似现象可以先查这几篇定位思路，但具体修复是否已合入、是否又被后续重构替换，必须看源码。
