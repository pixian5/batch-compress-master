# 命令行与本地化经验

## 1. 解析器自研，不依赖预览版 API

项目用自研 `CommandLineHandler` 替代早期的 `System.CommandLine`，理由是预览 API 变更会影响发布。
动词 `compress` / `extract` / `gui` 在解析前规范化为旧式 `--compress` / `--decompress` 开关，
保证老脚本不用改；错误文案走本地化资源，不硬编码中文。

## 2. 语言要在「完整解析成功后立刻」同步

`Program.Main` 解析成功后马上设置 `LocalizationService.CurrentLanguage`，
这样无界面运行期的服务层消息（开始、成功、跳过、缺卷）才和命令行输出同语言。
只改帮助文本、不改服务层，会出现英文提示夹中文消息的混排。
`--help` 不走完整解析，所以用预扫描 `DetectLanguage(args)` 提前决定帮助语言。

## 3. 语言值先归一再使用

`zh / zh-CN / zh-Hans → zh-CN`、`zh-TW / zh-Hant / tw → zh-TW`、`en-US → en`、`ja-JP → ja`、`de-DE → de`；
未知值报参数错误（退出码 2）。当前支持简体中文、繁體中文、English、日本語、Deutsch 五种。

## 4. 纯语言参数应该平滑启动图形界面

`--lang en` 不带模式动词、不带任何批处理意图时，按指定语言启动桌面程序；
但只要带了 `--input` / `--source` / `--output` / `--text-file` 等批处理意图，仍要求显式模式动词，
避免拼错的参数被「悄悄启动界面」掩盖。

## 5. 结构化输出要主动排除敏感内容

`--output-format json` 输出 NDJSON（每行一个 JSON 事件）时，人类可读提示改写 stderr，
stdout 只承载事件流；**含密码的命令行整条排除**，不进入事件。
退出码映射在这种模式下保持不变（0/1/2/130）。
**当前实测核实**：真实压缩的 json 模式在 stdout 产生 3 行事件
（`progress` / `item` / `summary`），`Found`、`Completed`、`Log file` 走 stderr，
且 stdout 搜不到 `--password-file` 里的明文密码。

**容易踩的边界（实测发现，历史文档未写）**：`--dry-run` 会提前返回，
不走结构化输出器——即使加了 `--output-format json`，stdout 也是**空的**，
DRY-RUN 清单写在 stderr。自动化脚本若依赖 NDJSON，不能拿试运行模式来联调。

## 6. 帮助文本的折行要考虑东亚宽字符

中文、日文字符在终端占 2 列，按字节或按字符数折行都会错位。
做法是：ASCII 按单词边界切分、东亚按单字切分、保持缩进并在长缩进时动态收缩；
输出被重定向到文件时保留原样，不做宽度折叠。

## 7. 退出码是脚本契约，不要随意改

| 码 | 含义 |
| --- | --- |
| 0 | 成功（含 `--help` / `--version` / `--dry-run` 正常结束） |
| 1 | 任务失败，或找不到可用归档引擎 |
| 2 | 参数错误、密码读取失败、来源路径校验失败 |
| 130 | Ctrl+C 协作式取消 |

`--dry-run` 只列任务，明确不创建输出目录、不写归档，可用于预检清单。
