# 语言切换下拉列表修复总结

## 问题描述
当用户切换应用语言时，某些下拉列表（如"来源模式"、"压缩级别"等）的文本不会立即更新。用户需要手动点击下拉列表才能看到更新的文本。

## 根本原因
在 Avalonia 框架中，使用静态 `ComboBoxItem` 元素并通过绑定到动态属性（如 `{Binding L.FromTxtMode}`）时，当属性的内部值改变但对象引用保持不变时，绑定不会自动刷新。

## 解决方案

### 方法：动态属性 + ItemsSource 绑定

在 ViewModel 中创建计算属性，每次访问时动态生成下拉列表项：

```csharp
/// <summary>
/// Dynamic source mode options that update when language changes
/// </summary>
public List<string> SourceModeOptions => new()
{
    L.FromTxtMode,
    L.CompressFolderMode
};
```

当语言改变时，显式触发属性变更通知：

```csharp
partial void OnSelectedLanguageChanged(string value)
{
    Localization.CurrentLanguage = value;
    
    // 触发 PropertyChanged 事件，使绑定刷新
    OnPropertyChanged(nameof(SourceModeOptions));
    // ... 其他属性通知
}
```

在 XAML 中使用 ItemsSource 绑定替代静态项：

```xaml
<ComboBox SelectedIndex="{Binding SourceMode}" ItemsSource="{Binding SourceModeOptions}" />
```

## 关键改动

### MainWindowViewModel.cs
- 添加计算属性：`SourceModeOptions`, `CompressionLevelOptions`, `ExistingFileModeOptions` 等
- 在 `OnSelectedLanguageChanged` 中显式通知这些属性的更改
- 调用 `Localization.NotifyPropertyChanged()` 确保所有订阅者得到通知

### MainWindow.axaml
- 将所有静态 ComboBoxItem 替换为 ItemsSource 绑定
- 绑定到相应的计算属性

## 优势

1. **自动更新**：无需手动调用 UI 刷新方法
2. **高性能**：动态生成列表与 ObservableCollection 相比，减少内存开销
3. **简洁**：代码逻辑清晰，易于维护
4. **Avalonia 推荐**：遵循框架最佳实践
