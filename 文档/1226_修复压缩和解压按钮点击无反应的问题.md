# 修复压缩/解压按钮点击无反应的问题

## 问题描述
当用户点击压缩或解压按钮时，程序没有任何反应，也没有显示任何错误信息。

## 问题原因
分析代码后发现，当 `SourceFileList` 为空时，点击压缩或解压按钮会直接返回，没有任何提示或自动加载文件列表的操作：

```csharp
if (sourcePaths.Count == 0)
{
    CommandLog += "No files to compress\n";
    return;
}
```

## 修复方案
修改了 `CompressAsync` 和 `DecompressAsync` 方法，添加了自动加载文件列表的逻辑：

### 1. CompressAsync 方法修改
在 `ViewModels/MainWindowViewModel.cs` 中：
- 当检测到 `SourceFileList` 为空时，自动调用 `RefreshFileListAsync()` 加载文件列表
- 加载后再次检查，如果仍然为空才显示错误信息

### 2. DecompressAsync 方法修改
在 `ViewModels/MainWindowViewModel.cs` 中：
- 在解析文件列表前检查 `SourceFileList` 是否为空
- 如果为空，自动调用 `RefreshFileListAsync()` 加载文件列表
- 加载后再次检查，如果仍然为空才显示错误信息

## 修复效果
- 用户点击压缩/解压按钮时，即使文件列表为空，也会自动尝试加载文件
- 如果加载成功，会继续执行压缩/解压操作
- 如果加载失败，会在命令日志中显示详细的错误信息
- 用户体验更加友好，不需要手动点击"更新列表"按钮

## 代码示例

### 压缩方法修复后的关键代码：
```csharp
// If no files in list, try to load them first
if (sourcePaths.Count == 0)
{
    CommandLog += "No files in list, trying to load automatically...\n";
    await RefreshFileListAsync();
    
    // Try again
    sourcePaths = SourceFileList.Split(new[] { '\r', '\n' }, StringSplitOptions.RemoveEmptyEntries)
        .Select(s => s.Trim())
        .Where(s => !string.IsNullOrEmpty(s))
        .ToList();
        
    if (sourcePaths.Count == 0)
    {
        CommandLog += "Still no files to compress\n";
        return;
    }
}
```

### 解压方法修复后的关键代码：
```csharp
// If source file list is empty, try to load automatically
if (string.IsNullOrEmpty(SourceFileList.Trim()))
{
    CommandLog += "No files in list, trying to load automatically...\n";
    await RefreshFileListAsync();
    
    // If still empty after refresh, show error
    if (string.IsNullOrEmpty(SourceFileList.Trim()))
    {
        CommandLog += "Still no files to decompress\n";
        return;
    }
}
```
