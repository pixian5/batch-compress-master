# RAR 与 7z 后端边界

GPT-5，2026-08-07：记录文件分类、命令参数隔离、格式能力差异和当前程序限制，避免把 WinRAR 参数误用于官方 7zz。

## 文件分类

以下分类是“通常情况”，不是对每个文件内容的检测结果。程序只把“通常已经压缩”的清单用于 RAR 的 `-ms`，不会因为扩展名把文件从归档中排除。

### 通常适合再次压缩

这些文件往往包含大量重复字节，适合使用正常压缩级别：

| 类别 | 示例 |
| --- | --- |
| 文本和日志 | `txt`、`csv`、`tsv`、`log`、`md`、`json`、`xml`、`yaml`、`yml` |
| 源代码和配置 | `c`、`cpp`、`h`、`cs`、`java`、`py`、`js`、`ts`、`html`、`css`、`sql`、`ini`、`conf`、`sh` |
| 原始图片或音频 | `bmp`、通常为 PCM 的 `wav` |
| 未压缩容器和旧文档 | `tar`、`doc`、`xls`、`ppt`、`rtf` |
| 原始或结构化数据 | `dat`，以及内容已确认没有内部压缩的数据文件 |

### 通常不适合再次压缩

这些文件通常已经经过压缩或编码，RAR 默认使用 `-ms` 仅存储：

| 类别 | 示例 |
| --- | --- |
| 归档和压缩流 | `rar`、`7z`、`zip`、`zipx`、`cab`、`ace`、`arj`、`lha`、`gz`、`bz2`、`xz` |
| 音频和视频 | `mp3`、`aac`、`m4a`、`flac`、`ogg`、`opus`、`mp4`、`mkv`、`mov`、`webm`、`avi`、`flv`、`rm`、`rmvb` |
| 压缩图片 | `jpg`/`jpeg`、`png`、`gif`、`webp`、`heic`、`avif` |
| 压缩文档容器 | `docx`、`xlsx`、`pptx`、`odt`、`ods`、`odp`、`odg` |

### 取决于内部内容

`pdf`、`tif`/`tiff`、`iso`、`dmg` 可能包含已压缩或未压缩数据，默认不强制归入前两类。扩展名不是内容检测：某个 WAV 可能使用压缩编码，某个 PNG 或 PDF 也可能包含大量可压缩数据。需要精确优化时，应按文件内容或实际压缩率决定，而不是只看扩展名。

## 两套命令严格隔离

### WinRAR/RAR

压缩入口是 `RarArchiveEngine`，参数由 `WinRarCommandBuilder` 生成。典型参数包括：

```text
a -ep1 -IBCK -SCf -m5 -s -rr5 -k -qo+ -t -z注释.txt -msmp4;mp3;rar;zip ... 输出.rar 输入
```

RAR 专属能力：

- `-ms`：按扩展名仅存储，文件仍然进入归档；
- `-rr`：恢复记录；
- `-k`：锁定归档；
- `-qo+`：快速打开信息；
- `-z`：从文本文件写入 RAR 注释；
- RAR 分卷和 WinRAR 的 RAR 退出码语义。

### 官方 7zz/7z 与 ZIP

压缩入口是 `SevenZipArchiveEngine`，参数由 `SevenZipCommandBuilder` 生成。7z 压缩示例：

```text
a -t7z -mx=9 -ms=on -p密码 -mhe=on -v20g 输出.7z 输入
```

ZIP 压缩示例：

```text
a -tzip -mx=9 -p密码 -mem=AES256 输出.zip 输入
```

7zz 解压示例：

```text
x -aoa -p密码 -o输出目录 输入.7z
```

7z/ZIP 专属或主要能力：

- `-t7z`、`-tzip`：选择输出容器格式；
- `-mx`：压缩级别；
- `-ms=on/off`：7z 固实压缩开关，这不是 WinRAR 的按扩展名 `-ms`；
- `-mhe=on`：7z 文件名加密；
- `-mem=AES256`：当前 ZIP 密码加密方式；
- `-ao*`：7zz 解压时的已有文件策略。

以下参数禁止跨后端传递：

| WinRAR 参数 | 不能传给 7zz 的原因 |
| --- | --- |
| `-ms扩展名列表` | 含义是 WinRAR 按扩展名仅存储，不是 7zz 的排除规则 |
| `-rr` | RAR 恢复记录，7z/ZIP 不支持同一语义 |
| `-k` | RAR 锁定归档 |
| `-qo+` | WinRAR 快速打开信息 |
| `-z文件` | 当前实现的 RAR 注释参数 |

| 7zz 参数 | 不能传给 WinRAR 的原因 |
| --- | --- |
| `-t7z`、`-tzip` | 7zz 的容器格式选择语法 |
| `-mx=N` | 7zz 压缩等级语法，RAR 使用 `-mN` |
| `-mhe=on` | 7z 文件名加密选项 |
| `-mem=AES256` | 7zz ZIP 加密选项 |
| `-aoa`、`-aos`、`-aou` | 7zz 解压已有文件策略 |

尤其不能把 WinRAR 的 `-ms` 改写为 7zz 的 `-xr`。`-xr` 是排除匹配文件，意味着文件不会进入归档，会造成数据缺失。

## 当前程序限制

- RAR 创建依赖项目内对应平台的 RAR/WinRAR 可执行文件和许可证资源；不同平台的 RAR 能力、许可证和退出码可能不同。
- macOS/Linux 使用官方 7zz 创建 7z/ZIP；Windows 也必须确认随包的 7zz 与平台架构匹配。
- 7z/ZIP 当前没有按扩展名的“仅存储”选项；它们会保留所有文件并使用统一压缩策略。
- RAR 的恢复记录、锁定、快速打开和注释不会迁移到 7z/ZIP。
- 7z 的文件名加密不能等同于 RAR 当前的密码参数；不同格式的密码不能直接互换，随机密码派生规则只能保持本程序入口一致。
- 后处理移动遇到目标冲突时现在保留源和目标，并统计为 `PostProcessFailCount`；它不会自动重命名、覆盖或合并目录。
- 分卷移动会先检查目标，发现任意一卷冲突就保留整组源卷；如果移动期间被外部程序改变文件状态，仍可能出现操作系统级别的移动失败，但不会主动删除目标。
- `-ms` 是基于扩展名的经验规则，不是文件内容分析。要判断单个文件是否值得再次压缩，应查看实际格式或比较压缩前后大小。
