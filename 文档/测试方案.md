# 批量压缩解压工具测试方案

## 1. 目的与范围

本文定义 `BatchCompress.Avalonia` 的发布前测试方法，覆盖 Avalonia GUI、命令行、归档引擎、macOS 应用包和回归自动化。目标是确认用户实际可完成压缩、解压、分卷、密码和日志查看，并且输入、输出和后处理符合预期。

本方案适用于当前开发版本。测试结论必须区分：

- **已实际验证**：命令或 GUI 操作已执行，且有产物、日志或校验和证据。
- **仅检查配置**：界面控件、帮助文案或参数存在，但未实际执行高风险动作。
- **平台待验证**：Windows、Linux、通知、托盘、系统关机及 RAR 可用性依赖目标环境，不能以 macOS 结果替代。

## 2. 测试层级

| 层级 | 目标 | 主要入口 | 通过条件 |
| --- | --- | --- | --- |
| 构建与单元 | 路由、参数、分卷解析和状态契约 | `BatchCompress.Avalonia.Tests` | 所有 `PASS`，构建无警告和错误 |
| CLI 全功能 | 格式、密码、后处理、分卷和错误码 | `测试夹具/全功能测试/run-all-tests.sh` | `TOTAL PASS=122 FAIL=0` |
| GUI 核心流程 | 用户在窗口内完成目录扫描、压缩、解压和日志操作 | macOS `.app` + Computer Use | 界面计数正确，产物和源文件校验和一致 |
| 安装包 | 发布包携带正确工具、可启动且为本次源码构建 | `scripts/package-macos.sh` | `/Applications` 应用可打开，7zz 可执行 |
| 平台回归 | 目标平台的路径、工具和系统集成 | 对应 OS/CI | 每个平台独立记录结论 |

## 3. 测试前置条件

1. 在仓库根目录执行全部命令，安装 .NET 10 SDK。
2. 使用 Release 构建。禁止将未指定配置的 `dotnet run --no-build` 作为验证依据，避免复用 Debug 产物。
3. RAR 用例需要已获授权的完整 `rar` 和 `unrar`。可通过 `BATCHCOMPRESS_RAR_PATH` 或 macOS 私有打包时的 `BATCHCOMPRESS_RAR_DIR` 提供；没有 RAR 时仅跳过 RAR 实测，不得把其标记为通过。
4. 7z、ZIP、TAR、GZ、BZ2、XZ、WIM 使用项目携带的官方 `7zz`。
5. 测试使用 `测试夹具/全功能测试`，其脚本会把原有 `输出/`、`临时/`、`生成物/` 移到 `/tmp/google-compress-e2e-backup.*`，再创建新数据。不要把用户真实文件放入该目录。
6. GUI 手工测试必须创建独立临时根目录，例如：

```zsh
gui_root="$(mktemp -d /tmp/batch-compress-gui-test.XXXXXX)"
mkdir -p "$gui_root/source/subdir" "$gui_root/output" "$gui_root/extract"
printf 'alpha\n' > "$gui_root/source/alpha.txt"
printf 'nested\n' > "$gui_root/source/subdir/nested.txt"
printf '中文路径\n' > "$gui_root/source/中文 空格.txt"
```

7. 除专门的隔离数据用例外，始终关闭“删除源”“移动源”“完成后关机”。不得以真实用户文件验证这些功能。

## 4. 执行顺序

### 4.1 构建与自动化回归

```zsh
dotnet restore
dotnet build BatchCompress.Avalonia.sln -c Release --nologo
dotnet run --project BatchCompress.Avalonia.Tests/BatchCompress.Avalonia.Tests.csproj \
  -c Release --no-build --nologo
zsh 测试夹具/全功能测试/run-all-tests.sh
```

记录构建输出、测试项目的每个 `PASS`，以及脚本最后一行 `TOTAL PASS=122 FAIL=0`。若脚本中有预期失败用例（错误密码、缺卷、锁定归档更新），以脚本的期望退出码通过为准，不能只看归档程序 stderr 是否出现错误。

### 4.2 macOS 打包与启动

```zsh
pkill -x BatchCompress.Avalonia || true
scripts/package-macos.sh
open /Applications/BatchCompress.Avalonia.app
```

检查项：

- 应用标题显示当前版本；窗口可见且没有启动崩溃。
- `/Applications/BatchCompress.Avalonia.app/Contents/MacOS/tools/7zip/macos/7zz` 存在且可执行。
- RAR 未注入时，GUI 与日志应明确反映 RAR 不可用，不得错误回退为 7zz 创建 RAR。
- GUI 使用完成后退出应用，避免影响下一轮打包。

## 5. GUI 详细用例

以下用例使用第 3 节的 `gui_root`。每次操作后检查顶部“成功/失败/忽略”计数、成功记录、失败记录和命令日志；执行归档操作后还必须进行文件系统核验。

| 编号 | 场景与操作 | 预期结果 | 证据 |
| --- | --- | --- | --- |
| GUI-01 | 启动应用，切换压缩配置、解压配置、开始、三类日志标签 | 每个标签可打开；开始页动作按钮随当前配置显示为“压缩”或“解压” | 截图或辅助功能树 |
| GUI-02 | 在压缩配置选择“压缩此文件夹内所有文件”，填写 `source` 与 `output`，点击更新列表 | 开始页出现 `alpha.txt`、`subdir`、`中文 空格.txt` 三项 | 来源列表和计数 3 |
| GUI-03 | 设置 `7z`，关闭随机密码、分卷、注释、附件；开启校验；填写自定义密码；确认危险后处理关闭 | 禁用控件随开关变化；临时目录和输出目录可编辑 | 配置截图/状态树 |
| GUI-04 | 从开始页执行压缩 | 三项成功、零失败；输出生成三个 `.7z` 文件；命令日志含 `7zz a` 和 `7zz t` | 成功记录、归档清单、日志 |
| GUI-05 | 在解压配置选择目录模式，来源为 `output`、目标为 `extract`，设置 `7z` 与相同密码，更新列表 | 列表为三个首卷归档；不把分卷的后续卷重复作为任务 | 来源列表和计数 |
| GUI-06 | 执行解压 | 三项成功、零失败；恢复 `alpha.txt`、中文空格文件和嵌套文件 | 成功记录和文件清单 |
| GUI-07 | 对源文件和解压文件逐个运行 `shasum -a 256` 或 `cmp -s` | 三个文件内容完全相同 | 校验和或 `cmp` 退出码 |
| GUI-08 | 依次打开成功记录、失败记录、命令日志 | 成功记录有 6 条操作结果；失败记录为 0；命令日志可读 | 日志页截图/导出 |
| GUI-09 | 点击“帮助”，确认快捷键、格式边界、托盘和关机提示；点击确定关闭 | 模态帮助正常出现与关闭 | 截图 |
| GUI-10 | 点击“更新列表”，然后“清空日志” | 更新后保留当前来源；清空后来源、成功、失败、命令日志计数均为 0 | 状态计数 |
| GUI-11 | 展开语言下拉菜单，检查简体中文、繁体中文、English、日本語、Deutsch 可选择；切换一种后切回简体中文 | 文案整体刷新、功能状态不丢失 | 切换前后截图 |
| GUI-12 | 验证“打开输出”“打开源”仅在临时目录中打开 Finder | Finder 定位到对应临时路径 | Finder 路径 |

### 5.1 GUI 参数覆盖矩阵

完整格式与异常覆盖交给第 6 节的脚本；GUI 每个版本至少完成一组真实往返。影响归档行为的 GUI 设置按下表抽样，并在功能变更时扩展为真实操作。

| 区域 | 代表值 | 预期 |
| --- | --- | --- |
| 格式 | 7z、zip、rar | 7z/zip 用 7zz；rar 仅用 RAR |
| 密码 | 随机、自定义、查询密码 | 归档按对应策略可解压；查询结果可复制 |
| 来源 | 文件夹、TXT 清单、拖放 | 文件夹扫描直系项目；TXT 每个非空行一项；拖放路径进入当前操作来源 |
| 分卷 | 关闭、1 MB | 关闭产生单文件；开启首卷命名正确且可由首卷解压 |
| 已有文件 | 覆盖、跳过、更新 | 与日志和实际输出策略一致；7z 更新解压使用不覆盖的命名策略 |
| 附件/注释 | 开关、存在/不存在附件 | 有效附件进入归档；不存在附件给出诊断，不产生假成功 |
| 后处理 | 删除、移动、关机 | 只使用专门生成的可丢弃文件；关机仅测试控件与取消流程，禁止真实关机 |
| 限制/取消 | 最大大小、长任务后 Esc | 达到限额停止后续项；取消不误报成功且 UI 恢复可操作 |

## 6. CLI 与归档引擎覆盖

`测试夹具/全功能测试/run-all-tests.sh` 是 Release 全功能回归的唯一标准入口，当前包含以下类别：

| 类别 | 覆盖内容 |
| --- | --- |
| 入口与参数 | `--help`、`--version`、命令别名、无效格式/级别/分卷/恢复记录、冲突参数和退出码 |
| 来源语义 | `--source` 直系扫描、`--input` 精确输入、重复路径去重、已处理标记、系统元数据过滤 |
| 创建格式 | 7z、ZIP、RAR、TAR、GZ、BZ2、XZ、WIM，含格式实际输出检查 |
| 密码与日志 | 文件、stdin、直接参数、随机密码、错误密码、原始命令日志与 quiet/verbose |
| 归档设置 | 压缩级别、固实、校验、注释、附件、临时目录、恢复记录、快速打开、锁定归档 |
| 输出策略 | 覆盖、跳过、更新、最大处理大小、删除源、移动源 |
| 分卷 | 7z、ZIP、RAR、TAR 创建、校验、首卷解压、SHA-256 内容校验、缺卷诊断 |
| 解压输入 | 单文件、多输入、目录扫描、TXT 密码本、重复密码本、已有文件策略和解压后处理 |

运行脚本后，测试产生物位于受忽略的 `测试夹具/全功能测试/输出/`、`临时/`、`生成物/`。这些目录是测试数据，不得加入提交。

## 7. 高风险功能的专项规则

### 7.1 删除与移动源文件

只在脚本自动生成的 `生成物/delete-source.txt`、`生成物/move-source.txt` 和 `生成物/delete-directory/` 上执行。验收应同时证明归档/解压结果存在、源已按配置处理、其他来源未受影响。

### 7.2 关机与托盘

禁止在常规自动化中实际调用关机。验收范围为：控件可用、帮助说明正确、已调度时可见“取消关机”并可取消。托盘需人工确认隐藏窗口后可通过菜单恢复和退出；不要把窗口关闭当作隐藏行为。

### 7.3 密码与日志

使用测试专用密码，禁止写入真实密码或私密归档。命令日志会保留归档程序原始参数，可能包含密码；收集截图、日志或问题报告前应检查并脱敏。

## 8. 平台与未覆盖边界

| 边界 | 验证方法 | 不可替代的环境 |
| --- | --- | --- |
| macOS | `.app` 安装、GUI 操作、内置 7zz、Finder、菜单栏托盘 | macOS Apple Silicon |
| Windows | WinRAR 检测、原生选择器、托盘、路径与注册表探测 | Windows 10/11 + 已授权 WinRAR |
| Linux | x64/ARM64 7zz、`notify-send`、桌面环境集成 | 对应 Linux 发行版与桌面会话 |
| RAR | 创建、测试、分卷和恢复记录 | 含 `rar` 与 `unrar` 的授权安装 |
| 取消 | 大型可丢弃数据运行中按 Esc | 需要足够长的实际归档操作 |

任何未在对应环境实测的项目都写为“未验证”，不得从构建、单元测试或另一平台测试推导为通过。

## 9. 缺陷分级与提交门槛

| 等级 | 定义 | 处理要求 |
| --- | --- | --- |
| P0 | 数据损坏、越界删除、错误关机、密码泄露或应用无法启动 | 阻断发布，立即停止相关操作 |
| P1 | 主流程压缩/解压失败、错误路由、分卷无法恢复 | 阻断发布，修复后完整回归 |
| P2 | 可绕过的设置、日志/计数错误、单个平台主要功能异常 | 修复后覆盖受影响矩阵和核心回归 |
| P3 | 文案、布局、非关键交互瑕疵 | 建单，合并前按优先级处理 |

合并或发布前必须满足：Release 构建无警告和错误、单元测试全通过、全功能脚本输出 `TOTAL PASS=122 FAIL=0`、至少一轮目标平台 GUI 核心往返通过，且没有未关闭的 P0/P1 缺陷。
