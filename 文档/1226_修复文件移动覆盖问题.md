当已解压文件夹里面已经有了要解压的文件之后，再次点击解压就无法把压缩文件移动到已解压文件夹里面去了，虽然我已经在已存在选择了覆盖。同理，如果要压缩的源文件也已经在已压缩文件夹里面存在。也无法把被压缩的文件移动到已压缩文件夹里。

## 问题分析
用户反馈当已解压/已压缩文件夹中存在同名文件时，即使选择了覆盖选项，处理后也无法将源文件移动到对应文件夹中。

## 原因分析
通过查看代码发现，问题出在`BatchOperationService.cs`文件中的文件移动逻辑：
1. 当执行文件移动操作时，`File.Move`和`Directory.Move`方法默认不支持覆盖
2. 如果目标路径已存在同名文件或目录，这些方法会抛出异常
3. 当前代码捕获了异常但没有处理，导致文件移动失败

## 修复过程
1. **修复压缩后移动源文件时的覆盖问题**（第343-374行）：
   - 在移动前检查目标路径是否存在
   - 如果目标存在（无论是文件还是目录），先删除它
   - 然后再执行移动操作

2. **修复解压后移动源文件时的覆盖问题**（第498-512行）：
   - 同样在移动前检查目标文件是否存在
   - 如果存在则先删除
   - 然后再执行移动操作

## 修复代码
压缩后移动源文件的修复：
```csharp
// 检查目标是否存在，如果存在则先删除
if (Directory.Exists(targetPath))
{
    Directory.Delete(targetPath, true);
}
else if (File.Exists(targetPath))
{
    File.Delete(targetPath);
}

if (Directory.Exists(sourcePath))
{
    Directory.Move(sourcePath, targetPath);
}
else if (File.Exists(sourcePath))
{
    File.Move(sourcePath, targetPath);
}
```

解压后移动源文件的修复：
```csharp
// 检查目标是否存在，如果存在则先删除
if (File.Exists(targetPath))
{
    File.Delete(targetPath);
}

File.Move(volumeFile, targetPath);
```

## 验证结果
- 程序运行正常，无编译错误
- 当已解压文件夹中存在同名文件时，再次解压后源文件能成功移动到已解压文件夹
- 当已压缩文件夹中存在同名文件时，再次压缩后源文件能成功移动到已压缩文件夹
- 覆盖功能正常工作

成功修复了文件移动时的覆盖问题，确保即使目标文件夹中存在同名文件，也能正常将源文件移动到对应文件夹中，提升了程序的健壮性和用户体验。
