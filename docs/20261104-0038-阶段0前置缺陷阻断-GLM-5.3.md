## 任务 0.1：`DescribeVolumeSuffix` 映射截断缺陷

- **核实**：`Math.Max` 截断使编号 1（主卷）与 2（首分卷）均输出 `r00`/`z01`。主卷缺失时实际走 `MissingFirstVolume` 分支不经过该函数，故属防御性缺陷，但映射歧义真实存在。
- **修复**：编号 1 显式返回 `rar`/`zip`，其余按偏移换算（`Core/Services/ArchiveVolumeResolver.cs`）。
- **断言**：新增 6 条显式断言（rar/r00/r01、zip/z01/z02）。

## 任务 0.2：`.z00` 与主卷编号撞车

- **核实**：`ZipOldStyleRegex` 匹配 `.z00` 后编号 0+1=1 与主卷撞号，误判重复编号而跳过整组。PKZIP 分卷从 `.z01` 起，`.z00` 非法。`.r00` 不受影响（RAR 合法首分卷，偏移 2）。
- **修复**：正则改为 `^(?<base>.+)\.z(?!00)(?<number>\d{2,})$`（`ParseVolumePattern` 与 `CreatePattern` 两处同步），`.z00` 不再入组、按未知文件处理。
- **断言**：`.z00` 存在时 `HasDuplicateNumbers=false`、组可解压、`.z00` 不在卷集合内。

## 任务 0.3：`PostProcessService` 语义偷渡解耦

- **核实**：删除失败词条此前借 `PreflightWholeGroup` 布尔区分压缩/解压，语义耦合（若压缩侧将来需要整组预检即崩）。
- **修复**：新增显式枚举 `PostProcessItemKind { CompressionSource, DecompressionArchive }`，`PostProcessRequest` 增加 `ItemKind` 字段，词条分支改按枚举判断；`PreflightWholeGroup` 只保留预检语义。两处调用方同步传值。

## 任务 0.4：表征测试盲区补齐（35 → 38 项）

1. **取消传播表征**：进入循环前取消（循环头即抛、引擎零调用、不关机）＋引擎执行中取消（外部 `CancelAfter(50)`、引擎延迟 400ms 后取消）——均抛 `OperationCanceledException`、`ShutdownCalls==0`、附件暂存目录在 finally 中可靠清理（扫描临时目录零残留）。
2. **Update 模式透传**：压缩侧 Update 不预删除已有输出、不跳过任务，`ExistingFileMode.Update` 原样传入引擎选项；解压侧同样透传（差异化由命令构建层 `-aou` 等实现）。
3. **CurrentFile 刷新基线**：解压预检失败（缺首卷）与压缩源不存在分支均在 `CurrentFile` 赋值前 continue，最后一次进度报告的 `CurrentFile` 保持上一成功项。
4. 基础设施：`ScriptedArchiveEngine` 增加 `CancelAfterMilliseconds`（执行中取消）与 `ThrowCancellationOnCompress`（预取消）能力，`CompressAsync` 改为真异步。
