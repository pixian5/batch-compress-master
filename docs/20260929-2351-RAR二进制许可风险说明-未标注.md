# RAR 二进制许可风险说明

日期：2026-09-29（2026-11-04 更新）
状态：**已落实方案 B（2026-11-03 用户决策）：仓库携带官方完整未修改 Linux x64 分发包，替换旧单文件裸二进制**

## 现状事实

- 仓库内保留一个 Linux x64 单文件可执行程序 `tools/rarLinux/rar`（798,760 字节，ELF 64-bit，2025-12-31 由提交 `e8173dd` 加入，至今仍在 git 追踪中，也存在于公开 GitHub 仓库和 git 历史里）。
- 该文件**只有 `rar` 一个可执行程序**，不含 `unrar`、`license.txt`、`order.htm`、`readme.txt` 等官方分发包的其余文件。
- 当前构建**不会**把它复制到输出目录：`BatchCompress.Avalonia.csproj` 只复制 `tools/7zip/**`。`RarArchiveEngine.GetLinuxCandidates()` 虽然把 `AppContext.BaseDirectory/tools/rarLinux/rar` 列为首选路径，但构建产物中该路径并不存在。
- 因此运行时的 RAR 能力实际来自：系统安装的 `rar`、`BATCHCOMPRESS_RAR_PATH` 指定的可执行文件，或 macOS 私有打包通过 `BATCHCOMPRESS_RAR_DIR` 注入的 `rar`/`unrar`。

## 许可依据（win.rar GmbH 终端用户许可协议原文）

来源：官方分发包内 `license.txt`（2026-08-06 下载的 `rarmacos-arm-723.tar.gz`，同样文本适用于各平台官方包）。

1. 第 2 条：软件为“先用后买”（try before you buy），试用期最长 40 天，之后用户须购买许可才能继续使用。
2. 第 3 条：试用版可自由分发，前提是**分发包不得有任何修改**（provided the distribution package is not modified in any way）。
3. 第 3a 条：**“Nobody may distribute separate parts of the package, with the exception of the UnRAR components, without written permission.”** —— 除 UnRAR 组件外，任何人不得分发该分发包的**独立部分**，除非取得书面许可。
4. 第 3b 条：未授权的试用版**不得打包进其它软件包**内分发（may not be distributed inside of any other software package），除非取得书面许可。

## 结论

- 仓库中只保存单个 `rar` 二进制，属于第 3a 条所指的“分发包的独立部分”，且 `rar` 不在 UnRAR 例外范围内；对外分发需要 win.rar GmbH 书面许可。
- 若再把它打包进 `.app` 或其它发布产物，还额外触碰第 3b 条。因此 `scripts/package-macos.sh` 依旧默认不注入 RAR，注入行为只在用户提供 `BATCHCOMPRESS_RAR_DIR` 时发生（由用户自行承担其授权责任）。
- 第 3 条允许的是“完整且未修改”的官方分发包；本项目当前形态不符合该条件。

## 用户决定（2026-09-29）

经确认，**保留现有裸二进制**，并在 README、架构文档与本文档中如实标注上述许可风险，不再沿用“公开仓库不携带任何第三方 RAR 二进制”的旧表述。

## 决策更新（2026-11-03 用户决策 B，2026-11-04 落实）

用户选择上述可选处置中的方案 2：**携带官方完整未修改分发包**。已于 `0.6.16` 落实：

- `tools/rarLinux/` 现为官方 `rarlinux-x64-723.tar.gz`（来源 https://www.rarlab.com/rar/rarlinux-x64-723.tar.gz ，
  tarball SHA-256 `759b4b6aa0d9f77131882162951193f3a0e54bf60e1d8dc4255aa308accab588`）
  的**完整解包内容**：`rar`、`unrar`、`default.sfx`、`license.txt`、`order.htm`、`rar.txt`、
  `rarfiles.lst`、`readme.txt`、`whatsnew.txt`、`acknow.txt`、`makefile`，共 12 个文件，未做任何增删修改。
- 旧单文件 `tools/rarLinux/rar` 已删除。值得记录的事实：旧裸二进制与官方 7.23 包内的 `rar`
  **尺寸相同（798,760 字节）但 SHA-256 不同**（旧 `c9dcacb4…` vs 官方 `56c3c4fd…`），
  即旧文件本就无法验证为“未修改的官方组件”；新文件可凭上方哈希完整溯源。
- `BatchCompress.Avalonia.csproj` 在 Linux 构建下**整体复制** `tools/rarLinux/**`
  （含 license.txt 等全部文件），不拆包、不挑选单个二进制——满足许可第 3 条“完整且未修改”
  的分发前提，规避第 3a 条“不得分发独立部分”。
- `RarArchiveEngine.GetLinuxCandidates()` 首选路径 `tools/rarLinux/rar` 与构建输出一致，已加注释说明。
- macOS 打包脚本行为不变：默认不注入 RAR，仅在用户提供 `BATCHCOMPRESS_RAR_DIR` 时注入
  （第 3b 条“不得打包进其它软件包”仍由该边界控制，由注入方自行承担授权责任）。

## 发行版选择更新（2026-11-07，批次 14 / v0.7.8）

为满足对许可合规有极严格要求的用户与分发渠道需求，`scripts/package-linux.sh` 现支持 `--no-rar` 构建开关：
- 执行 `bash scripts/package-linux.sh --dist --no-rar` 将剔除 `tools/rarLinux` 分发包，产出 `BatchCompress.Avalonia_<版本>_linux-x64-no-rar.tar.gz` 纯净版本。
- 纯净版本只依赖开源 7-Zip（7zz），完全回避任何 RAR 许可条款（第 3 条与第 3b 条）的法律争议；7z/zip/tar 等格式功能完备，RAR 能力遵循运行时系统环境后备。
