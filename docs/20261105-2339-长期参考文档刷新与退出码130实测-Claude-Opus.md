## 三、Ctrl+C 退出码 130 实测（补上一轮留白）

### 三次尝试与失败原因

| 尝试 | 结果 | 追查 |
| --- | --- | --- |
| 1 | 退出码 0，归档全生成 | 后台范围写错，整条 `&&` 链被放进后台；且 150 MB 随机数据 1.2 秒内压缩完，信号到达前任务已结束 |
| 2 | 退出码 0，3 个归档全生成 | **非交互 shell 启动的后台作业默认忽略 SIGINT（中断信号）**，`kill -INT` 被丢弃 |
| 3 | **退出码 130** | 在子进程里 `zsh -c 'trap - INT; exec "$@"' _ ...` 重置信号处置后再启动程序，信号被 `Console.CancelKeyPress` 捕获 |

第三次实测输出要点：

```
=== 退出码: 130 ===
=== 日志取消记录 ===
[WARNING] Operation cancelled by user (Ctrl+C)
[WARNING] Operation was cancelled
=== 产物数 === 1（共 3 个任务，后续任务未启动）
=== 残留 7zz 进程 === 无
```

这同时印证了经验库里「取消会杀整棵子进程树」「关机只在非取消正常结束时触发」两条约束。

### 纳入可复跑脚本

第 13 项加入 `测试夹具/经验验证/verify.sh`：造三份较大文件串行压缩，
子进程重置 SIGINT 后发中断，检查退出码 130、日志取消记录、无残留 `7zz` 进程。
可用 `SKIP_CANCEL_TEST=1` 跳过这项较重的用例。脚本现在共 **16 项**。

**复跑结果：PASS=16 FAIL=0**（含原有 15 项与新增取消用例）。

新增经验写入 `经验/04-进程与并发.md` 第 8 节（自动化测取消的信号坑），
`经验/05-命令行与本地化.md` 的退出码表补实测结论，
`文档/COMMAND_LINE.md` 与 `经验/README.md` 同步。

- 取消时**可能留下已经写出或半途写出的归档**（第三次实验产物数为 1）。
