# 修复 macOS 图形界面启动竞态

## 问题

在 macOS 启动图形界面时，Avalonia Native 会创建基于 CoreVideo `CVDisplayLink` 的渲染计时器。如果应用恰好在显示器唤醒、切换、登录项启动或 WindowServer 短暂重建显示状态的窗口内初始化，`CVDisplayLinkCreateWithActiveCGDisplays` 会返回 `-6661`（`kCVReturnInvalidArgument`）。Avalonia 随后在窗口创建前抛出：

```text
Avalonia.Native was not able to start the RenderTimer. Native error code is: -6661
```

这不是压缩或解压引擎错误；它会使整个 GUI 进程在显示任何窗口前退出，因此用户无法进入“压缩、解压、日志”选项卡。无界面压缩/解压不会触发该路径。

## 修复

`Program.Main` 在进入 Avalonia 生命周期前，仅对 macOS 调用同一个 CoreVideo API 做预检查：

1. 创建临时 `CVDisplayLink`，成功后立即释放。
2. 等待 100 毫秒再次创建并释放，要求连续两次成功，以跨过显示器状态切换竞态。
3. 失败时每 500 毫秒重试；每 10 秒向标准错误输出一次等待提示。
4. 显示链恢复后才调用 `BuildAvaloniaApp().StartWithClassicDesktopLifetime(...)`。

这样 Avalonia 不会收到已知会失败的初始化状态。没有可用显示器时程序保持等待，因为此时 macOS 本身无法呈现可操作窗口；显示器恢复后会自动继续。Windows、Linux 和命令行压缩/解压路径不调用 CoreVideo，也不受影响。
