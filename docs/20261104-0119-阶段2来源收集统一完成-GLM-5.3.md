## 2. 缺陷背景与修复原理

**历史缺陷**：GUI 在来源文本框输入带尾部斜杠的目录（如 `/path/to/dir/`）时，
路径原样进入批处理循环，`Path.GetFileName("/path/to/dir/")` 返回**空串**，
压缩输出文件名变成 `.7z` 空名归档；后处理移动源目录时还会因名字为空产生自引用错误。
CLI 侧 `CollectCompressionSources` 只做 `GetFullPath`（不消除尾分隔符）同样带病。

**修复**：所有收集出口统一经过 `SourceCollector.NormalizePath`：

```
Trim → GetFullPath（相对转绝对）→ 根路径守卫 → TrimEnd(两个目录分隔符)
```

- 根路径守卫：`GetFullPath("/") == "/"`，再 TrimEnd 会得到空串；Windows 上
  `C:\` → `C:` 会退化为盘符相对路径，均须原样返回；
- 非法路径（NUL、非法字符等）不抛异常，返回去空格原文，交由
  `BatchOperationService` 按 `ItemNotFound` 报告计数，与历史 GUI 行为一致；
- 解压目录收集先规范化再做 `File.Exists` 判断：POSIX `stat("file/")` 对普通文件
  返回 ENOTDIR，历史实现会把带尾斜杠的文件行误判为不存在而静默丢弃。

## 3. SourceCollector API 设计

| 方法 | 职责 | 服务的调用端 |
| :--- | :--- | :--- |
| `NormalizePath(string?)` | 规范化单条路径（上文四处语义） | 全部出口共用＋测试直测 |
| `SplitLines(string?)` | 与旧 `Split({'\r','\n'}, RemoveEmptyEntries)` 逐字一致的拆分；保留行内原文（密码本空行剔除影响配对，不能提前 Trim） | 内部共用 |
| `CollectCompressionSourcesFromText / (IEnumerable<string>)` | 压缩来源统一收集：Trim、空行/元数据过滤、规范化、忽略大小写保序去重；不做存在性过滤（缺失项由服务层计 `NonExistCount` 报告） | GUI `CompressAsync`（两处）、CLI `--input`/`--source` |
| `CollectPasswordBookEntries(string?)` | 解压密码本交替行（文件/密码步进 2）：保留历史配对语义（空行剔除、缺失文件整对跳过）＋规范化 | GUI `DecompressAsync` 密码本模式 |
| `CollectDecompressionFilesFromText / (IEnumerable<string>, extension)` | 解压文件行：Trim、元数据过滤、存在性＋格式校验、规范化；**不去重**（跨条目分卷折叠与去重由服务层执行并计入 `IgnoreCount`，保持表征锁定口径） | GUI 目录模式、CLI 精确项等价入口 |
| `CollectDecompressionEntries(seed, rawPaths, ext, skipProcessed, service)` | CLI 解压任务收集：文件→格式校验＋首卷折叠、目录→`LoadArchivesFromFolder` 展开、元数据过滤＋全路径去重（种子密码本条目优先保留密码） | CLI `CollectDecompressionEntries` |

职责边界：TXT 密码本/压缩清单的**文件级导入与诊断**（`LoadFilesFromTextFileWithDiagnostics`
等）仍属 `BatchOperationService`；`SourceCollector` 只负责路径/文本行层面的统一。

### 有意的行为差异（均为缺陷修复方向，逐项说明）

1. **尾斜杠路径**（核心修复）：GUI/CLI 全部出口规范化，`GetFileName` 不再返回空串；
2. **GUI 压缩源新增保序去重**：历史行为下重复行会压缩两次（第二次命中既有输出策略），
   现按指令“去重保持顺序”收敛为一次；
3. **CLI `--input` 存在性过滤移除**：`ValidateSourcePaths` 已在收集前校验全部路径
   （缺失即退出码 2），原 `.Where(File.Exists…)` 属冗余防御；极端竞态下（校验后、收集前
   被外部删除）条目不再被静默丢弃，而是进入服务的 `ItemNotFound` 报告——与 GUI 口径一致；
4. **密码本/文件行收集新增规范化**：带尾斜杠的文件行从“静默丢弃”变为正确识别；
   TXT 密码本**文件**导入路径未改动（服务层职责，行为不变）。
