## 2. 主要问题（按严重度）

### 2.1 结构性问题

1. **压缩/解压双循环重复**：`BatchOperationService.BatchCompressAsync`（L346-L609）与 `BatchDecompressAsync`（L676-L951）共享 15 个步骤——元数据过滤、存在性校验、跳过已处理、密码解析、`ArchiveOptions` 构建、开始消息、引擎调用、命令输出转发、成功/失败统计、后处理、最终消息、`Elapsed`、大小上限、关机。差异只有三处：输入准备（解压需分卷解析）、引擎调用参数、后处理目标集合（单路径 vs 多卷整组）。
2. **ViewModel 双流程重复**：`CompressAsync`（L793-L932）与 `DecompressAsync`（L934-L1102）的进度回调几乎逐行相同（L849-L900 与 L1019-L1070），包括统计映射、速度/剩余时间、通知、三分类日志；`try/catch/finally`、完成摘要、取消提示也重复。
3. **来源收集两套实现**：GUI 在 `MainWindowViewModel` 内按行 Split（L822、L975-L1008），CLI 在 `HeadlessBatchRunner.CollectCompressionSources` 另写一套；密码本交替行、扩展名匹配、跳过已处理等规则容易漂移。
4. **视图层承载业务逻辑**：`MainWindow.axaml.cs`（789 行）包含拖放解析、目录/TXT 选择、附件选择、关机确认与帮助对话框，部分可直接下沉到 ViewModel/Service。

### 2.2 功能与合规缺口

5. **旧式分卷未识别**：`ArchiveVolumeResolver` 仅支持 `.partN.rar`、`.7z.N`、`.zip.N`、`.<ext>.N`（L72-L86）；`.r00`、`.z01` 会被当成独立单卷任务，失败并污染统计。
6. **CLI 语言不可控**：CLI 不构造 ViewModel，`LocalizationService` 保持 `zh-CN`；CLI 自带文案为英文、服务层消息为中文，脚本输出不稳定，也无 `--language` 选项。
7. **RAR 二进制许可风险未闭环**：仓库仍保留 `tools/rarLinux/rar`（798 KB），且 `RarArchiveEngine.GetLinuxCandidates()` 首选路径在构建产物中不存在。
8. **无 CI**：三平台构建与测试完全依赖本地手工执行；无回归门禁。

### 2.3 质量与卫生

9. **测试覆盖偏科**：30 项集中在命令构建、分卷解析、引擎路由与本地化；`MainWindowViewModel`、`BatchOperationService` 的后处理矩阵、CLI 密码/路径解析缺少自动化覆盖。
10. **文档断链**：工作区已有未提交修改把 README/ARCHITECTURE 指向新命名的 `docs/` 文件，但根目录 `文档索引.md` 尚不存在。
11. **仓库冗余**：`Trae.md` 与 `glm.md` 内容重复（各约 33 KB）、`seed开发方案.md` 为早期方案稿、`old/` 与 `BatchCompress.Avalonia/` 为历史副本；缺 `LICENSE`。
12. **密码明文落盘**：`ArchiveProcessRunner` 的 `CommandLine` 与归档程序 stdout/stderr 原样进入日志（`BatchOperationService.ReportArchiveOutput` L1023-L1057），这是既定策略（便于核对），但日志文件无权限收紧与轮转策略。

## 4. 详细设计

### 4.1 P0：执行管线重构

#### 4.1.1 目标结构

```
BatchOperationService（对外门面，保留现有公开方法）
  └─ BatchExecutionPipeline（新，泛型模板）
       ├─ IBatchItemAdapter<TInput>（压缩/解压各一个实现）
       ├─ PostProcessService（后处理策略）
       └─ BatchProgressReporter（统一计数与消息）
```

#### 4.1.2 接口草案

```csharp
// 单条任务准备结果；Prepare 返回 null 表示已报告跳过原因，模板不再执行。
public sealed record PreparedBatchItem(
    string SourcePath,          // 压缩为源路径；解压为首卷路径
    string DisplayName,         // 消息展示名（文件名）
    string OutputPath,          // 压缩为归档路径；解压为输出目录
    string Format,              // 归一化格式
    string? Password,
    IReadOnlyList<string> PostProcessPaths, // 删除/移动目标（解压为整组卷）
    long? MeasuredBytes);       // 统计口径（压缩为输出大小，解压为归档大小）

public interface IBatchItemAdapter<TInput>
{
    Task<PreparedBatchItem?> PrepareAsync(
        TInput input, BatchOperationOptions options,
        BatchRunContext context, CancellationToken ct);

    Task<ArchiveResult> ExecuteAsync(
        PreparedBatchItem item, BatchOperationOptions options, CancellationToken ct);

    // 后处理失败时使用的条目类型文案（压缩源 / 解压归档）
    string PostProcessItemLabel { get; }

    // 处理量统计
    long MeasureProcessedBytes(PreparedBatchItem item, ArchiveResult result);
}

public sealed class BatchExecutionPipeline
{
    public Task ExecuteAsync<TInput>(
        IReadOnlyList<TInput> inputs,
        IBatchItemAdapter<TInput> adapter,
        BatchOperationOptions options,
        IProgress<OperationProgressInfo> progress,
        CancellationToken ct);
}
```

模板固定顺序（与现实现一致）：

```
初始化 progressInfo
foreach input:
  ct.ThrowIfCancellationRequested()
  prepared = adapter.PrepareAsync(...)   // 跳过/错误已在内部 report
  if null: continue
  报告 Started 消息
  result = adapter.ExecuteAsync(...)
  ReportArchiveOutput(result)
  if success:
    SuccessCount++；累计字节；PostProcessService.Apply(...)
    消息 = ItemSucceeded 或 ItemSucceededWithPostProcessFailure
  else:
    FailCount++；消息 = ItemFailed（解压额外 CleanupFailedExtractionOutput）
  Elapsed 更新；progress.Report
  MaxSizeGB 达到则报告并 break
完成日志；ShutdownAfterComplete 则请求关机
```

#### 4.1.3 后处理策略

```csharp
public sealed record PostProcessRequest(
    PostProcessMode Mode,               // Delete / Move
    IReadOnlyList<string> Targets,
    string ProcessedFolderName,         // "【已压缩】" 或 "【已解压】"
    string ItemLabel,                   // 本地化条目类型
    bool PreflightWholeGroup);          // 解压多卷：整组冲突预检

public sealed record PostProcessOutcome(bool Failed, string Reason);

public sealed class PostProcessService
{
    public PostProcessOutcome Apply(PostProcessRequest request);
}
```

- 压缩：`PreflightWholeGroup=false`，单路径删除/移动。
- 解压：`PreflightWholeGroup=true`，先整组检查目标存在，冲突则保留整组并只计一次失败。
- `TryMoveWithoutOverwrite` 与 `RecordPostProcessFailure` 原样迁入，保持跨平台覆盖语义。

#### 4.1.4 ViewModel 侧

新增 `OperationSession`（不依赖 Avalonia）：

```csharp
public sealed class OperationSession
{
    public Task<OperationSessionResult> RunAsync(
        OperationKind kind,                 // Compress / Decompress
        SourceCollectionResult sources,
        BatchOperationOptions options,
        IProgress<OperationProgressInfo> progress,
        CancellationToken ct);
}
```

`OperationProgressPresenter` 统一处理：统计映射、速度/剩余时间、`MaybeShowProgressNotification`、三分类日志（`IsCommandOutput` 优先）。`CompressAsync`/`DecompressAsync` 缩减为“解析来源 → 建 options → 调用 session → 展示摘要”，预计 ViewModel 减少约 200 行。

#### 4.1.5 迁移步骤

1. 先补 14 项表征测试（见 4.6），锁定现有消息文本、计数与退出行为。
2. 引入 `PostProcessService` 并从两个循环中替换（行为不变，先跑测试）。
3. 引入 `BatchExecutionPipeline`，压缩先迁入，再迁解压；两循环最终只剩 `Prepare/Execute` 适配器。
4. 引入 `OperationSession`，ViewModel 两个命令收敛为一个内部方法。
5. 全量回归 + macOS 打包实测。

### 4.2 P0：来源收集统一

#### 4.2.1 设计

```csharp
public enum SourceCollectionMode { Folder, TextList, PasswordBook }

public sealed record SourceCollectionRequest(
    SourceCollectionMode Mode,
    string? FolderPath,
    string? TextFilePath,
    string? FormatExtension,
    bool SkipAlreadyProcessed,
    bool ForDecompression);

public sealed record SourceItem(string Path, string? Password, long Size);

public sealed record SourceCollectionDiagnostics(

    IReadOnlyList<string> Ambiguous,
    IReadOnlyList<string> DuplicateVolumes,
    IReadOnlyList<string> UnmatchedArchives,

public sealed record SourceCollectionResult(
    IReadOnlyList<SourceItem> Items,
    SourceCollectionDiagnostics Diagnostics);

public sealed class SourceCollector { public SourceCollectionResult Collect(SourceCollectionRequest request); }
```

- 现有 `BatchOperationService.LoadFilesFromFolder(..., isForDecompression)`、`LoadCompressionPathsFromTextFile`、`LoadFilesFromTextFileWithDiagnostics` 迁入 `SourceCollector`；保留 `isForDecompression` 语义（压缩不按格式过滤源文件，解压只筛归档）。
- GUI：`LoadFromTextFileAsync`/`LoadFromFolderAsync` 只负责渲染诊断（`L.*` 词条）。
- CLI：`HeadlessBatchRunner.CollectCompressionSources` 删除，改调 `SourceCollector`。
- 诊断保持对象化，不拼接人类可读文本，避免两套文案。

#### 4.2.2 验收

- 三种来源 × 压缩/解压共 6 条路径在新旧实现下输出一致（含密码本交替行、缺卷、歧义、大小写）。
- 新增 6 项测试。

### 4.3 P1：旧式分卷识别

- `ArchiveVolumeKind` 增加 `RarOldStyle`、`ZipOldStyle`。
- 正则：`^(?<base>.+)\.r(?<number>\d{2,})$`、`^(?<base>.+)\.z(?<number>\d{2,})$`（忽略大小写）。
- 解析规则：`.r00`/`.z01` 属于 `base.rar`/`base.zip` 的分卷；主卷（`.rar`/`.zip`）必须存在且为第 1 卷；编号连续性按数值检查（`r00 → 1`）。
- 同步覆盖：`HasArchiveExtension`、`IsMultiVolumeArchive`、`ResolveOutputFiles`（压缩时删除已有分卷输出）、`MatchesFormat`。
- 目录扫描遇到 `.r00`/`.z01` 时归入主卷任务，不单独成项。
- 测试 5 项：完整 r00 组、缺主卷、缺中间卷、z01 组、大小写混合。

### 4.4 P1：CLI 语言与结构化输出

- 新增 `CommandLineOptions.Language`，参数 `--language, --lang`，取值与 `AvailableLanguages` 一致，默认 `zh-CN`；解析成功后设置 `LocalizationService.Instance.CurrentLanguage`。
- 新增 `--output-format <text|json>`（默认 `text`）。
- JSON 采用 NDJSON（每行一个对象）：

```json
{"type":"progress","phase":"start","source":"a.rar","message":"开始解压: a.rar"}
{"type":"item","status":"success","source":"a.rar","successCount":1,"failCount":0,"postProcessFailCount":0}
{"type":"summary","success":1,"failed":0,"postProcessFailed":0,"ignored":0,"nonexistent":0,"incompleteVolumes":0,"ambiguous":0,"elapsedSeconds":3.2}
```

- 密码与命令原文不进入 JSON；仅在日志文件保留（维持现有策略）。
- 帮助文本改为本地化词条（至少中英双语），`--help` 受 `--language` 影响。
- 退出码保持：0 成功、1 任务失败、2 参数错误、130 取消。
- 测试 4 项：语言参数生效、JSON 行可解析、摘要计数正确、退出码不变。
