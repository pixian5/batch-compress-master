## 1. 结论摘要

- CLI、压缩引擎、解压引擎、密码本、后处理和异常路径均已使用可复现夹具执行。
- RAR、7z、ZIP 的普通单卷压缩、解压、密码、中文/空格/特殊字符、嵌套目录和空文件均通过。
- RAR 分卷压缩/解压通过；7z 和 ZIP 分卷创建通过，但 7z 分卷启用 --test 时校验阶段失败，这是当前实现的 P1 缺陷。关闭 --test 后 7z/ZIP 分卷创建和解压通过。

## 11. 已确认问题

### P1：7z 分卷与 --test 校验路径不兼容

SevenZipArchiveEngine 创建分卷后以基础路径执行 7zz t。7zz 生成 .7z.001 等卷，基础 .7z 不存在，校验失败并返回 1，但卷文件已经生成。

~~~bash
dotnet run --project BatchCompress.Avalonia.csproj --no-build -- compress \
  --input '测试夹具/全功能测试/生成物/大文件.bin' \
  --output '测试夹具/全功能测试/输出/vol7z' \
  --format 7z --volume-size 1 --volume-unit m --no-random-password --test
~~~

证据：生成物/vol7z.log。RAR 分卷和 ZIP 分卷对照通过。

### P2：--quiet 失败时 stderr 为空

帮助和 文档/COMMAND_LINE.md 声明 quiet 只向 stderr 输出错误。错误密码命令退出 1，但 wrong-password.stdout 和 wrong-password.stderr 均为空，错误只进入日志。应保留错误摘要到 stderr，同时避免普通进度输出。

### P2：--enclosure-list 帮助和实现语义不一致

帮助写“文件”，实现却把参数值直接按换行分割，不打开该文件。传入 附件清单.txt 时，文件本身被当附件。应读取文件内容，或把帮助改为“换行分隔的路径字符串”，并同步文档。

### P2：GUI 手工来源文本列表缺少去重

CLI 路径收集有 Distinct，而 MainWindowViewModel.cs:679-694 手工文本列表直接逐行处理，重复行可能执行多次。GUI 无法启动，本轮未交互复现。

### P2：7z 使用绝对输入路径时归档内可能保留路径组件

extract-7z 出现 测试夹具/全功能测试/来源目录/普通文本.txt 这样的归档内路径；RAR 使用 -ep1 后为相对顶层文件名。需明确并统一跨格式路径语义。

### P2/文案：过时的 WinRAR/7z 警告

Localization/LanguageStrings.cs 和 Localization/LocalizationService.cs 保留“WinRAR 无法压缩 7z”历史文案。当前 7z 使用官方 7zz；本轮未发现文案实际调用，但建议清理或改写。
