## 3. 架构成熟度演进

## 5. 批次 6 交付明细

1. **打包脚本**：`package-macos.sh --dist`（.app→zip，向后兼容历史安装模式与 CI 调用；
   修复一处 zip 写入 stage 被误删的缺陷）；`package-windows.sh`（win-x64 自包含 zip，Unix 交叉）；
   `package-linux.sh`（linux-x64 tar.gz，强制核验 7zz 与 tools/rarLinux 完整包随产物）；
   `package-all.sh` 统一入口（平台参数或 all）；四脚本均含 `--check` 环境自检。
2. **Release 工作流**（`.github/workflows/release.yml`）：`v*` tag / 手工触发；
   三平台 48 项测试为硬门禁；macOS runner 产 `.app.zip`＋ubuntu runner 交叉产
   win zip 与 linux tar.gz；tag-VERSION 一致性校验＋三产物齐全核验；
   `gh` CLI（runner 预装＋内置 token）创建 Release 上传附件，零第三方 action 依赖。
3. **本地实测边界（如实声明）**：零流量约束下本地仅缓存 osx-arm64 runtime pack——
   macOS 打包全流程实测（0.7.0 命名、plist 版本注入、zip 结构）；win/linux 交叉发布
   需 runtime pack 本地缺失，脚本经 `bash -n`＋`--check` 验证，真实产物由 Release 工作流
   首跑（GitHub 侧联网）产出。
4. **版本链**：`VERSION=0.7.0` → csproj → `--version` 输出 → Info.plist → 产物命名，全链验证一致。

## 7. 复盘要点（供未来项目复用）

1. **表征先行**：动深水区前先用 17 场景锁行为，之后每步全绿再前进——六批次零回归的根本原因；
2. **两步法与逐行核对**：一次只迁一半；`git diff` 删除行归一化比对让"零漂移"成为可验证声明；
3. **冒烟必须可区分**：并发功能的验证必须含耗时/峰值类证据（批次 5 教训：透传静默缺失时
   功能冒烟仍"通过"）；
4. **脚本替换必须断言命中**：文本锚点不符时静默失败是真实发生过的缺陷模式；
5. **许可合规走完整包**：第三方二进制整包携带＋哈希溯源，优于裸文件＋文档声明；
6. **安全默认值**：日志 0600、并发默认 1、NDJSON 排除命令输出——新能力默认安全，
   向后兼容由默认值保证。
