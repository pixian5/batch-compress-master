# 下一步待实现

日期：2026-09-30 00:52
基于版本：`0.6.4`

## 高优先级

1. **RAR 二进制最终处置**
   当前按用户决定保留裸二进制并标注风险（见 [RAR 二进制许可风险说明](202609292351RAR二进制许可风险说明.md)）。三条可选路径：移除、改携带完整官方分发包、或取得 win.rar GmbH 书面许可。
   附带一致性问题：`RarArchiveEngine.GetLinuxCandidates()` 的首选路径在构建产物中不存在，应在“让该二进制生效”和“删除该死路径”之间二选一。

2. **CLI 输出语言策略**
   命令行模式不会构造 `MainWindowViewModel`，因此 `LocalizationService` 保持默认 `zh-CN`：CLI 自带文案为英文，服务层消息为中文，且用户无法切换或固定语言。建议为 CLI 增加语言选项（或固定为英文），保证脚本输出稳定。

3. **旧式分卷识别**
   `ArchiveVolumeResolver` 只识别 `.partN.rar`、`.7z.N`、`.zip.N`、`.<ext>.N`；目录扫描遇到 `xxx.r00`、`xxx.z01`（`ArchiveFormatCatalog` 中已有别名）会作为独立单卷任务进入解压并失败，污染成功/失败统计。需要补充识别或显式跳过并提示。

## 中优先级

4. **CI 与测试基建**
   仓库暂无 `.github/workflows`。建议增加 Windows/macOS/Linux 三平台矩阵工作流，执行 `dotnet build` 与测试控制台（当前 30 项）。测试项目仍只链接 Core 与 CLI，`MainWindowViewModel` 的列表解析、选项映射、标签状态保存等纯逻辑没有自动化覆盖。

5. **GUI 与 CLI 来源收集逻辑统一**
   `HeadlessBatchRunner.CollectCompressionSources` 与 ViewModel 的列表解析是两套实现，容易在密码本模式、格式匹配规则上产生语义漂移，建议下沉到 `BatchOperationService` 统一。

6. **运行时切换语言后托盘文案刷新（新发现）**
   运行中切换语言后，非 macOS 托盘菜单与 macOS 状态栏帮助进程的菜单文案不即时刷新，重启后才生效（当前已在 `App.axaml.cs` 注明）。可选方案：切换语言时重建托盘图标与帮助进程。

## 低优先级（卫生类）

7. **仓库冗余文件**：`Trae.md` 与 `glm.md` 内容完全相同（MD5 一致，各 33KB），`seed开发方案.md` 为早期方案稿，建议移入 `文档/` 归档或删除。
8. **缺少 LICENSE 文件**：公开仓库未声明本项目自身许可，建议补充（与 RAR/7-Zip 第三方许可区分开）。
9. **密码算法说明**：`PasswordUtility` 使用 MD5 派生（为兼容旧版密码而保留），建议在 README 显著位置提醒该算法不构成密码学保护。
10. **硬编码业务内容**：`MainWindowViewModel` 中附件列表默认值写死了邮箱/微信/QQ 联系方式，建议外置为配置或资源。
