## 二、交付内容

### 1. `--language / --lang` 纯 GUI 平滑启动（`CommandLineHandler.cs` + `Program.cs`）

- **现状问题**：`batchcompress --lang en` 因未提供模式动词触发 `CliErrorSpecifyMode` 报错退出（退出码 2），用户被迫写 `gui --lang en`。
- **实现**：
  - `ParseState` 新增 `LanguageRequested`，仅在 `--language/--lang` 的值**有效**（能通过 `TryNormalizeLanguage` 归一）时置位；
  - 新增 `ShouldDefaultToGui(options, languageRequested)` 判定：`languageRequested && 无 SourcePath && 无 OutputPath && 无 TextFile && InputPaths 为空`——即"纯语言调用、零批处理意图"；
  - `options.Gui` 赋值与 `Validate` 的 SpecifyMode 校验统一接入该判定：命中则默认 GUI，未命中（携带 `--input/--source/--output/--text-file`）仍要求显式模式，**防止误启动 GUI 掩盖参数错误**；
  - 语言切换链路复用批次 3/4 既有机制：`DetectLanguage` 预扫描在解析开始即切换全局语言，`Program.Main` 解析成功后再次同步，随后自然落入 GUI 分支，桌面程序以指定语言启动；`gui --lang <lang>` 显式语义保持不变；
  - `--lang fr`（无效值）仍按退出码 2 拒绝（`LanguageRequested` 不置位，不影响错误路径）；
  - 简体/繁体/英文三份帮助文本的 `--language` 条目补充"单独使用且不带模式动词时直接以该语言启动图形界面"说明。
- **效果**：`./BatchCompress.Avalonia --lang en`、`--lang ja`、`--language=zh-TW`、`--lang en-US`（区域变体归一）等均直接启动对应语言桌面程序。

### 2. 多代日志轮转与磁盘防护（`FileLoggerService.cs`）

- **现状问题**：超过阈值仅轮转单代 `.1`，`.1` 再次超限时被直接覆写，历史日志丢失。
- **实现**：
  - `RotateIfOversized` 升级为标准多代滚动：先 `ShiftRotatedGenerations()` 删除超限最旧一代（`.N`），再从高代到低代依次后移（`.N-1→.N` … `.1→.2`），最后当前文件改名为 `.1` 并新建同名日志继续写入；
  - 新增公开常量 `DefaultRotatedGenerations = 5` 与构造参数 `maxRotatedGenerations`（`>=1`，非法回退默认），默认保留 `.1`–`.5` 共 5 代；
  - **0600 权限保持**：`File.Move` 继承原文件已收紧的 Unix 模式，新当前文件由 `InitializeWriter`→`RestrictLogFilePermissions` 重新收紧，实测全部代均为 `UserRead|UserWrite`；
  - `PruneExpiredLogs` 过期清理由两个固定模式（`.log`、`.log.1`）泛化为通配 `batchcompress_*.log*` 粗筛 + `IsBatchCompressLogName` 正则（`\.log(\.\d+)?$`）精筛，覆盖任意代次；Windows 三字符扩展名匹配放宽的边界由正则兜底；
  - 轮转失败仍为尽力而为（警告 + 恢复写入器），不影响批处理主流程。

### 3. 并发管线轻量级吞吐优化与资源释放审查（`BatchExecutionPipeline.cs`）

- **锁内精简**（缩短高并发下 `gate` 临界区内的文件 I/O 与字符串格式化）：
  - 任务启动日志 `Log(StartedLogMessage)` 移出锁外（消息不依赖共享进度对象；`FileLoggerService` 自带线程安全锁）；
  - 成功完成消息（`ItemSucceeded`/`ItemSucceededWithPostProcessFailure`）的 `string.Format` 移到锁外预构建，锁内只做计数回写与快照上报；
  - "Size limit reached" 日志经 `sizeLimitJustReached` 标志移出锁外，临界区内只保留状态切换、进度上报与 `gateCts.Cancel()` 信号；
  - 后处理失败警告日志**保持**在锁内 `RecordPostProcessFailure` 统一记录——与串行路径共用同一实现，避免双写（实施中发现并纠正了一处预写导致的重复日志风险）。
- **资源释放审查结论**：`engineCts`、`gateCts`、`semaphore` 均为 `using` 声明，无论 `Task.WhenAll` 正常结束、外部取消（`OperationCanceledException` 聚合传播）还是适配器真实异常向上传播，离开方法时都确定性释放；`CreateLinkedTokenSource` 对外部令牌的注册随 Dispose 撤销，`SemaphoreSlim` 句柄归还；全部 `Task.Run` 任务被 `WhenAll` 观测，不存在未观察任务异常或句柄泄漏路径。结论以代码注释形式固化在 `RunConcurrentAsync` 顶部。
