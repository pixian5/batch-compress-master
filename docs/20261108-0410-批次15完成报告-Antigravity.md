## 2. 关键代码变更与架构实现

### 2.1 ViewModel 领域分解 (`ViewModels/MainWindowViewModel.*.cs`)
原 `MainWindowViewModel.cs` 达 1,491 行，职责混合了窗口生命周期、文件选取、批处理执行、状态机流转与附件持久化。本次采用 C# `partial class` 拆分：
- **`MainWindowViewModel.cs`（841 行）**：主视图模型核心，保留响应式属性（`[ObservableProperty]`）、窗口生命周期与选项卡状态机；
- **`MainWindowViewModel.BrowsingAndFiles.cs`（296 行）**：专职目录选择对话框、文件选取、TXT 清单/密码本读取与输入体积计算；
- **`MainWindowViewModel.Execution.cs`（345 行）**：批处理压缩与解压执行主循环、进度汇报绑定、取消与日志清空；
- **`MainWindowViewModel.Enclosures.cs`（40 行）**：附件联系方式的保存与重置。
> 编译保证：0 警告，Avalonia 编译期绑定与 CommunityToolkit.Mvvm 代码生成完全正常。

### 2.2 测试程序领域分解 (`BatchCompress.Avalonia.Tests/Program.*.cs`)
原测试入口 `Program.cs` 包含 63 项测试与模拟桩，单文件达 3,914 行。本次将其重构为 `internal static partial class Program`：
- **`Program.cs`（558 行）**：保留 `Main` 测试驱动表、聚合执行调度、测试失败汇总输出、通用断言及共享模拟引擎（`TestArchiveEngine`、`RecordingArchiveEngine` 等）；
- **`Program.CliTests.cs`（533 行）**：11 项命令行解析、多语言参数、错误文案本地化与终端宽度折行测试；
- **`Program.EngineTests.cs`（683 行）**：14 项归档引擎参数生成、分卷命名解析、7zz 冒烟与 RAR 7zz 回退测试；
- **`Program.PipelineTests.cs`（1,357 行）**：25 项并发批处理、管道流转、取消与残片快照回滚测试；
- **`Program.LoggingAndConfigTests.cs`（783 行）**：11 项多代日志轮转、Gzip 容灾降级、附件外置与 NDJSON 契约测试；
- **`Program.LocalizationTests.cs`（231 行）**：4 项多语言资源扫描、窗口标题与非中文检查测试。

### 2.3 RAR 7zz 解压回退与 Linux ARM64 明确诊断 (P2-10)
- **解压回退**：`ArchiveEngineRouter.cs` 在 `ExtractAsync` 中，若识别到输入为 RAR 格式但本地未安装 WinRAR/RAR（例如 macOS 或 Linux ARM64），且官方 7zz 可用时，自动转发至 `_sevenZipEngine.ExtractAsync`。官方 7zz 原生支持 Rar/Rar5 解压，解压过程完全透明；
- **Linux ARM64 诊断**：在 `RarArchiveEngine.GetMissingRarMessage()` 中，当检测到处于 Linux ARM64 架构且缺少 RAR 程序时，返回明确诊断提示：
  `"RAR executable not found on Linux ARM64 (bundled RAR binary is provided for Linux x64 only). Please install system rar or use 7z/zip format."`；
- **测试覆盖**：在 `Program.EngineTests.cs` 中实现 `TestRarExtractionFallbackToSevenZip`，验证 RAR 缺失自动回退、两引擎全缺失报错及文案非空。

### 2.4 NDJSON 机器可读契约 (P3-12)
- 创建 `schemas/ndjson-schema-v1.json`，基于 JSON Schema Draft-07 严格规定三类事件：
  1. `progress`（过程进度）：`phase`、`source`、`message`；
  2. `item`（条目完成）：`status`（`success|fail|skip`）、`source`、`message` 及 7 项排他计数增量；
  3. `summary`（批次总结）：最终 7 项计数汇总与 `elapsedSeconds` 秒级耗时；
- 在 `Program.LoggingAndConfigTests.cs` 中实现 `TestNdjsonSchemaValidation`，实机生成三类事件并对字段与类型进行严格断言。

### 2.5 目标平台产物实机验证接入发布工作流 (P1-7)
在 `.github/workflows/release.yml` 中新增 `verify-artifacts` 任务：
- 矩阵调度：`linux-x64`（ubuntu-latest）、`win-x64`（windows-latest）、`macos-arm64`（macos-latest）；
- 步骤：下载各自平台的自包含发布压缩包，解包后实机运行 `./BatchCompress.Avalonia --version`，比对与仓库 `VERSION` 完全一致；随后执行真实的单文件压缩与解压闭环，校验还原内容逐字节一致；
- 作为 `release` 作业的前置依赖（`needs: [package-macos, package-cross, verify-artifacts]`），确保发布的二进制包绝无架构错误或缺失依赖。
