2. **服务层诊断日志目前完全不可见（新发现）**
   `BatchOperationService` 的 `Log()` 依赖构造函数注入的 `ILogger`，但 GUI 与 CLI 两个入口都没有传入 logger，因此这些 `Log(LogLevel.Warning/Error/…)`（含“删除源失败”“移动源失败”“解压归档目标已存在，已保留整组源卷”“清理解压失败残留失败”等）不会出现在任何地方。表现为：界面只显示“成功但后处理失败: X”，却看不到失败原因。
   建议二选一：为两个入口注入 `ILogger`（GUI 可写入 `FileLoggerService`），或把后处理失败原因改为 `progress.Report()` 消息，使其进入失败记录。

## 中优先级

4. **CLI 输出语言策略**
   命令行模式不会构造 `MainWindowViewModel`，因此 `LocalizationService` 保持默认 `zh-CN`：CLI 自带文案为英文，服务层消息为中文，且用户无法切换或固定语言。建议为 CLI 增加语言选项（或固定为英文），保证脚本输出稳定。

5. **旧式分卷识别**
   `ArchiveVolumeResolver` 只识别 `.partN.rar`、`.7z.N`、`.zip.N`、`.<ext>.N`；目录扫描遇到 `xxx.r00`、`xxx.z01`（`ArchiveFormatCatalog` 中已有别名）会作为独立单卷任务进入解压并失败，污染成功/失败统计。需要补充识别或显式跳过并提示。

6. **CI 与测试基建**
   仓库暂无 `.github/workflows`。建议增加 Windows/macOS/Linux 三平台矩阵工作流，执行 `dotnet build` 与测试控制台（当前 29 项）。测试项目仍只链接 Core 与 CLI，`MainWindowViewModel` 的列表解析、选项映射、标签状态保存等纯逻辑没有自动化覆盖。

7. **GUI 与 CLI 来源收集逻辑统一**
   `HeadlessBatchRunner.CollectCompressionSources` 与 ViewModel 的列表解析是两套实现，容易在密码本模式、格式匹配规则上产生语义漂移，建议下沉到 `BatchOperationService` 统一。
