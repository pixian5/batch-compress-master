## 一、任务背景

随着项目各底层机制的成熟，本次交付聚焦于**用户体验盲区修复**与**CLI 国际化死角清理**：
1. **剩余时间显示盲区**：在原有实现中，剩余时间（`RemainingTime`）和完成时刻（`EstimatedCompletionTime`）仅当 `TotalSizeGB > 0.01` 时才触发计算。然而，在以下常见场景中：
   - 全部“解压”操作（解压前无法预估展开后的总大小）；
   - 从文本列表/文件列表导入待处理项；
   - 快速目录扫描未预计算目录深层体积；
   导致界面中“剩余时间”恒定显示为 `00:00:00`，严重影响用户对长批次进度的把握。
2. **CLI 密码读取硬编码死角**：在 `HeadlessBatchRunner.TryResolvePassword` 中，当标准输入读取密码失败时，错误提示写死为中文 `"无法从指定来源读取密码。"`，在 `--lang en`、`--lang ja`、`--lang de` 模式下存在语言混杂。

## 二、交付内容清单

### 1. 解压与无大小预估场景 ETA 智能兜底算法
- **会话总条目注入**：
  - 在 `ViewModels/OperationSession.cs` 中增加 `_totalItems` 状态与 `SetTotalItems(int)` 方法；
  - 在 `MainWindowViewModel.CompressAsync` 与 `DecompressAsync` 准备好 `sourcePaths.Count` 与 `entries.Count` 后，第一时间向会话注入当前批次待处理项总数。
- **双引擎自适应 ETA 计算**：
  - **优先路径（体积优先）**：若 `TotalSizeGB > 0.01 && ProcessedSizeGB < TotalSizeGB`，继续基于实时 `MB/秒` 吞吐与剩余字节计算微秒级精确 ETA；
  - **兜底路径（均速平滑）**：当总大小未预估但总条目数有效（`_totalItems > 0`）时，在首批项目完成并运行超过 0.5 秒后，依据已完成项（`Success + Fail + Ignore`）的单项平均耗时自动外推剩余项完成时间：
    $$\text{RemainingTime} = \frac{\text{ElapsedTime}}{\text{CompletedItems}} \times (\text{TotalItems} - \text{CompletedItems})$$
    $$\text{EstimatedCompletionTime} = \text{Now} + \text{RemainingTime}$$
  - 完成时精准归零（`RemainingTime = TimeSpan.Zero`）。
