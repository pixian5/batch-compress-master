## 3. 契约设计说明

### 3.1 IBatchItemAdapter&lt;TInput&gt;

| 成员 | 职责 |
| :--- | :--- |
| `PrepareAsync(input, options, progressInfo, progress)` | 元数据过滤、存在性检查、跳过已处理、分卷/输出解析、密码生成、构建 `ArchiveOptions`。跳过或预检失败时自行更新计数、上报进度并返回 `null`；按各自历史时序刷新 `progressInfo.CurrentFile`。 |
| `ExecuteAsync(item, ct)` | 调用底层引擎执行压缩/解压，包裹异常路径清理（压缩侧附件暂存目录 finally 删除）。 |
| `MeasuredBytes(item, processedSizeGBBefore)` | 成功后大小统计（压缩：分卷输出求和＋基础路径回退；解压：整组分卷求和＋列表大小回退＋竞态告警），返回字节数。 |
| `BuildPostProcessRequest(item, options)` | 后处理目标集合＋词条＋整组预检语义（任务书的 `PostProcessPaths` 要点在此以完整请求对象实现，语义更完整）。 |
| `OnExecutionFailed(item)` | 引擎失败（返回失败结果）后的残留清理；压缩空实现，解压回滚新写出文件。 |
| `BuildBatchCompletedLogMessage` / `ShutdownRequestLogMessage` | 批次完成诊断日志与关机前诊断日志（解压侧有 "Shutdown requested after completion"，压缩侧历史无此日志，保留差异）。 |

### 3.2 PreparedBatchItem（抽象基类）

承载管线所需的共性字段：`DisplayName`（消息用条目名）、`CurrentSourcePath`（GUI 行定位）、
`Options`（引擎选项）、`StartedMessage`（本地化启动消息）、`StartedLogMessage` /
`SucceededLogMessage`（诊断日志）、`CommandLabel`（命令输出转发前缀）、抽象
`BuildFailedLogMessage(errorMessage)`（压缩/解压失败措辞不同）。

- `PreparedCompressionItem`：`SourcePath` / `OutputPath` / `StagingDirectory`。
- `PreparedDecompressionItem`：`ArchivePath` / `Resolved` / `Entry` ＋ `ExecuteAsync` 填充的
  `OutputDirectory` / `OutputDirectoryExisted` / `OutputSnapshot`（失败回滚用）。

### 3.3 BatchExecutionPipeline&lt;TInput&gt;.RunAsync

收敛六项共性骨架：循环遍历、`cancellationToken.ThrowIfCancellationRequested()`、进度上报
（含启动消息、成功/失败消息、Elapsed 报告）、`ReportArchiveOutput` 命令输出转发
（原 `CloneProgress` 快照防串扰逻辑原样迁入）、`PostProcessService.Apply` 调用＋失败逐条计数、
`MaxSizeGB` 超限 break＋`SizeLimitReached` 报告、非取消正常结束时的 `ShutdownAfterComplete` 关机。
取消异常向上传播时不触达关机分支，与原双循环一致。

## 5. 零漂移保障措施

- **表征测试**：17 个场景的断言均为消息逐字比对（`string.Format(L.Xxx, ...)` 相等）、
  七类计数断言、文件系统副作用断言、关机次数断言，迁移后全部原样通过。
- **逐行核对**：从 `git diff` 提取服务中删除的全部 618 行，逐行在管线/适配器新文件中查找
  字面对应；67 行未字面匹配项逐一归类复核，全部属于三类预期等价改写：
  1. 变量经条目抽象重命名（`name`→`DisplayName`、`archiveOptions`→`item.Options`、
     `sourcePath`→`prepared.SourcePath`、`normalizedFormat`→`_normalizedFormat` 等）；
  2. 消息/日志经适配器数据等价生成（`BuildFailedLogMessage`、`BuildBatchCompletedLogMessage`、
     `CommandLabel`、`ShutdownRequestLogMessage`，文本与原插值逐字一致）；
  3. 大小统计统一路径（`processedSizeGB += measuredBytes / BytesPerGB`，与原
     `sizeGB = bytes / (1024.0*1024.0*1024.0); processedSizeGB += sizeGB` 数值恒等；
     压缩侧 `if (outputBytes > 0)` 守卫等价于加 0.0 恒等式）。
- **时序保留**：压缩 `CurrentFile` 赋值先于【已压缩】跳过、解压去重先于 `CurrentFile` 赋值、
  附件暂存目录创建于启动报告前/删除于引擎调用 finally、解压输出目录创建于启动报告后、
  不可创建格式在进入循环前报告且不触发关机——全部保持原顺序。
- **共享可变快照语义**：管线整批共用一个 `OperationProgressInfo`（与原双循环一致），
  `CurrentFile 刷新基线` 表征测试正是靠该别名效应锁定，迁移后语义未变。

## 6. 遗留与移交

- `BatchOperationService` 现仅保留：公共 API（目录/文本扫描、TXT 密码本与压缩清单导入、
  大小统计、双入口方法）＋ `internal static BuildIncompleteVolumeMessage`（解压适配器与
  TXT 导入共用，含注释契约说明）。
- `MainWindowViewModel.cs` 仍为 1,673 行，属阶段 3（`OperationSession`）范围，本阶段不动。
- 发现的可优化点（已按“主动告知”原则记录，未擅自扩大范围）：
  1. 压缩与解压适配器的 `PrepareAsync` 返回 `Task.FromResult`（逻辑本身全同步），
     保留 `Async` 后缀是为对齐任务书契约，未来若引入异步预检可直接落地；
  2. `DecompressionItemAdapter` 持有整批 `BatchOperationOptions`（因 `ExecuteAsync`
     契约不含 options），若后续契约演进可考虑把输出目录解析全部前移到 `PrepareAsync`，
     但那会改变“输出目录创建于启动报告之后”的历史时序，需表征测试同步调整，本阶段不做。
